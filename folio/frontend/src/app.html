Scoring method and limitations

Each case runs independently through the same answer pipeline as chat, with no conversation history. The run freezes the model configuration and document IDs; use a fresh run to compare a changed model or dataset. The corpus stays scoped to your account.

Retrieval metrics use the first six ranked passages before any general-answer fallback. Expected sources are document-level labels, so these metrics cannot prove a passage contains the exact answer. General-chat cases have no retrieval score. Unlabeled cases are excluded from retrieval averages.

Accuracy is the fraction marked Correct among reviewed, successful AI answers. Check review coverage and failure rate alongside it; a small or selected test set is not proof of overall quality. Reference token F1 is lexical similarity, not a correctness judge. No automatic LLM judge or fabricated accuracy score is used.

Provider requests may use quota. Runs pause after the first failed case; completed or started cases cannot execute twice. Pause stops scheduling new requests after the current case finishes. A request interrupted by a server restart can remain Running; create a new run rather than risk duplicate provider charges.

Results are stored in your account database. Free Render storage can reset after restarts or deploys: export results and test sets you want to keep. JSON exports include questions, references and generated answers, but no API keys.
